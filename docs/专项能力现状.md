# MakeJob 专项能力现状

本文档基于当前代码状态更新于 `2026-05-15`，专门记录最容易被误判的三条主线：AI 面试、学习闭环、题目流水线。

## 1. AI 面试现状

### 1.1 当前不是纯 HTTP 文本问答

当前面试链路已经同时具备：

- 面试创建与历史查询
- WebSocket 实时会话
- TTS 音频播报
- ASR 录音上传与识别结果展示
- Live2D 面试官舞台
- 面试报告页
- 编程题模式下的代码编辑与过程事件记录

对应关键代码：

- 后端：`backend/internal/handler/interview_handler.go`
- 后端：`backend/internal/service/interview_service.go`
- 前端：`frontend-react/apps/web/src/features/interview/InterviewSessionPage.tsx`
- 前端：`frontend-react/apps/web/src/features/interview/InterviewLive2DStage.tsx`

### 1.2 当前真实边界

虽然实时链路已经落代码，但完整体验仍受以下因素影响：

- TTS provider 是否可用
- ASR provider 是否可用
- Live2D 资源是否完整
- 浏览器麦克风权限是否正常

因此正确判断应是：

- 代码层面：已接通主链路
- 环境层面：仍需配置与联调

## 2. 学习计划、陪伴、成长档案现状

### 2.1 当前已经不是分散模块

这三块已经形成闭环：

- 学习计划负责生成和维护任务主线
- 学习陪伴负责聊天推进和每日记录
- 成长档案负责聚合练习、计划、面试和周重点补强

对应关键代码：

- `backend/internal/handler/plan_handler.go`
- `backend/internal/service/plan_service.go`
- `backend/internal/handler/companion_handler.go`
- `backend/internal/service/companion_service.go`
- `backend/internal/handler/growth_handler.go`
- `backend/internal/service/growth_service.go`
- `frontend-react/apps/web/src/features/companion`
- `frontend-react/apps/web/src/features/growth/GrowthPage.tsx`

### 2.2 当前已经落地的能力

- 生成学习计划
- 查询当前计划和历史计划
- 更新任务状态
- 提交任务反馈
- 动态调整计划
- 学习陪伴聊天
- 每日学习日志同步
- 成长档案总览
- 本周重点补强
- 推荐练习和错因专题跳转

### 2.3 当前正确认知

不要再把成长档案理解成“登录后占位页”，当前它已经是学习闭环的聚合落点。

## 3. 题目流水线现状

### 3.1 当前不是只有导入接口

题目流水线目前已经有一条完整后台工作流：

- 输入岗位要求和提示词
- 选择抓取来源
- 同步生成候选题卡
- 流式逐张生成候选题卡
- 记录失败调试信息和原始输出
- 恢复异步生成任务结果
- 勾选、编辑和导入题卡
- 交给 worker 消费异步任务

对应关键代码：

- 后端：`backend/internal/handler/admin_handler.go`
- 后端：`backend/internal/service/admin_question_pipeline*.go`
- 后端：`backend/cmd/worker/main.go`
- 前端：`frontend-react/apps/admin/src/features/question-pipeline/QuestionPipelinePage.tsx`

### 3.2 当前实际运行方式

题目流水线有两种模式：

- 同步 / 流式：只启动 API 即可体验
- 异步：除 API 外还必须启动 worker

### 3.3 当前正确认知

不要再把题目流水线理解成“概念文档”或“后端半截实现”，它已经是后台现有重点功能之一。

## 4. 当前最值得优先关注的风险

### 4.1 环境风险高于代码骨架风险

当前最容易影响使用的不是“有没有页面 / 有没有接口”，而是：

- 数据库与 Redis 是否就绪
- AI / TTS / ASR 配置是否可用
- Live2D 资源是否齐全
- Worker 是否已启动

### 4.2 敏感配置治理需要尽快统一

仓库当前存在开发环境配置与敏感信息治理问题，后续如继续对外协作或部署，必须先收口。

## 5. 重新接手本项目时的建议切入点

如果你要重新接手专项能力，建议这样看：

1. 先看 `../start.md` 确认启动方式
2. 看 `./接口与模块清单.md` 确认真实路由
3. 前台专项从 `InterviewSessionPage.tsx`、`GrowthPage.tsx`、`CompanionWorkspacePage.tsx` 切入
4. 后台专项从 `QuestionPipelinePage.tsx`、`RuntimeTasksPage.tsx` 切入
5. 后端专项从 `interview_service.go`、`plan_service.go`、`admin_question_pipeline*.go` 切入
