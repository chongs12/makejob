# MakeJob 微服务改造现状报告

> 生成日期: 2026-06-11

## 一、项目概览

**MakeJob** 是一个面向求职面试场景的 AI 驱动学习平台，采用 Go 语言微服务架构。项目基于 **Kratos v2** 框架构建，使用 **gRPC** 进行服务间通信，**Gin** 作为网关 HTTP 框架。

### 核心技术栈

| 组件 | 技术选型 |
|------|----------|
| 微服务框架 | Kratos v2.8.3 |
| HTTP 网关 | Gin v1.12.0 |
| 依赖注入 | Wire v0.7.0 (实际使用手动组装) |
| 数据库 ORM | GORM v1.31.1 (PostgreSQL) |
| 服务发现 | etcd v3.5.5 (已预留，未实际使用) |
| 消息队列 | RabbitMQ (amqp091-go v1.10.0) |
| 向量数据库 | Milvus v2.6.5 |
| 认证 | JWT v5.3.1 |
| API 定义 | Protocol Buffers + buf |
| 可观测性 | Prometheus + Grafana + Jaeger (OpenTelemetry) |
| LLM 集成 | 火山引擎 ARK (字节跳动云) |
| 语音 | 火山引擎实时语音 (WebSocket) |
| 代码执行 | Piston (远程代码执行引擎) |

## 二、15 个微服务一览

### 1. gateway -- HTTP API 网关
- **端口**: HTTP :8082
- **职责**: 唯一 HTTP 入口，REST -> gRPC 转换，CORS/JWT 认证/响应格式统一化
- **存储**: 无

### 2. user -- 用户服务
- **端口**: gRPC :9101, HTTP :8101
- **职责**: 注册、登录、JWT Token 管理、用户资料 CRUD、Token 黑名单(Redis)
- **存储**: PostgreSQL (users) + Redis (token_blacklist)

### 3. question -- 题库服务
- **端口**: gRPC :9003, HTTP :8003
- **职责**: 题库浏览、刷题、收藏/笔记、推荐、考试、错题本、题目集、MQ 异步消费
- **存储**: PostgreSQL (questions, categories, industries, user_records, favorites, notes, exams, question_sets)

### 4. interview -- 面试服务
- **端口**: gRPC :9004, HTTP :8004
- **职责**: 模拟面试会话、答题、编程题、报告生成、实时语音上下文、MQ 消费
- **存储**: PostgreSQL (mock_interviews, interview_messages, interview_coding_attempts, interview_reports)

### 5. admin -- 管理后台服务
- **端口**: gRPC :9014, HTTP :8014
- **职责**: 仪表盘、用户/题库/分类/行业管理、Prompt/AI/Live2D/TTS/RAG 配置、面经爬虫、题目流水线
- **存储**: PostgreSQL (admin_configs)，聚合下游 user/question/interview/ai_gateway/rag

### 6. ai_gateway -- AI 网关服务
- **端口**: gRPC :9011, HTTP :8011
- **职责**: 统一 LLM 调用网关，封装火山引擎 ARK API，多种 AI Agent (Interview/Plan/Companion/QuizAnalyzer/ResumeParser/Live2DDirector)
- **存储**: PostgreSQL (ai_configs, prompt_templates, ai_call_logs)

### 7. growth -- 成长服务
- **端口**: gRPC :9006, HTTP :8006
- **职责**: 用户学习成长数据聚合(学习天数/练习统计/面试统计/计划进度/弱项/每周聚焦)
- **存储**: PostgreSQL (聚合表)，调用 question/plan/archive/interview 四个下游

### 8. plan -- 学习计划服务
- **端口**: gRPC :9007, HTTP :8007
- **职责**: AI 驱动的学习计划生成、任务管理、反馈诊断、进度追踪、MQ 消费
- **存储**: PostgreSQL (plans, tasks, task_feedbacks, plan_adjustments)

### 9. community -- 社区服务
- **端口**: gRPC :9009, HTTP :8009
- **职责**: 帖子 CRUD、评论、点赞、我的帖子
- **存储**: PostgreSQL (posts, comments, likes)

### 10. membership -- 会员服务
- **端口**: gRPC :9002, HTTP :8002
- **职责**: 会员状态、套餐列表、订单管理、支付回调、功能权限校验
- **存储**: PostgreSQL (orders, memberships)

### 11. companion -- 陪伴助手服务
- **端口**: gRPC :9008, HTTP :8008
- **职责**: AI 陪伴聊天、情绪状态管理、TTS 语音合成
- **存储**: PostgreSQL (companion_states)

### 12. realtime -- 实时语音服务
- **端口**: gRPC :9005, HTTP :8085 (含 WebSocket)
- **职责**: 实时语音面试、WebSocket 代理、RAG 上下文注入、火山引擎实时语音对接
- **存储**: PostgreSQL (realtime_sessions)

### 13. coderunner -- 代码执行服务
- **端口**: gRPC :9013, HTTP :8013
- **职责**: 代码执行(Piston 远程引擎)、语言列表查询
- **存储**: 无，纯计算服务

### 14. rag -- RAG 检索增强服务
- **端口**: gRPC :9012, HTTP :8012
- **职责**: Milvus 向量检索、题目/文档索引、RAG 配置、MQ 消费(题目同步)
- **存储**: Milvus (makejob_questions)，使用火山引擎 ARK Embedding

### 15. learning_archive -- 学习档案服务
- **端口**: gRPC :9010, HTTP :8010
- **职责**: 学习档案条目写入/查询、弱项分析、聚焦信号提取、MQ 消费(面试完成事件)
- **存储**: PostgreSQL (archive_entries)

## 三、服务间通信

### 同步调用 -- gRPC 直连

所有服务间通信采用 **gRPC 直连**，通过配置文件硬编码地址。etcd 服务发现已预留 (`pkg/discovery/etcd.go`) 但未实际启用。

```
前端 --> gateway (HTTP) --> user / question / interview / growth / plan
                        --> admin / companion / community / membership

interview --> ai_gateway, learning_archive, rag, coderunner
question  --> ai_gateway, coderunner, admin
growth    --> question, plan, learning_archive, interview
admin     --> user, question, interview, ai_gateway, rag
plan      --> ai_gateway
realtime  --> interview, rag
companion --> ai_gateway
```

### 异步调用 -- RabbitMQ

Exchange: `makejob.async` (topic)，9 个队列:

| 路由键 | 生产者 | 消费者 | 用途 |
|--------|--------|--------|------|
| `plan.generate` | gateway/admin | plan | 计划生成 |
| `plan.feedback.diagnosis` | plan | plan | 反馈诊断 |
| `interview.resume.parse` | interview | interview | 简历解析 |
| `interview.report.generate` | interview | interview | 报告生成 |
| `interview.archive.persist` | interview | interview | 归档持久化 |
| `scraper.import.questions` | admin | question | 爬虫导入 |
| `admin.question.pipeline.build` | admin | question | 题目流水线 |
| `rag.sync.question` | question | rag | 题目同步 |
| `interview.finished` | interview | learning_archive | 面试完成事件 |

### 认证机制

- **外部**: JWT Token，gateway 验证后注入 user_id/role 到 context
- **内部**: 服务间 `ServiceAuthInterceptor` 自动注入 service-token
- **黑名单**: Redis 维护已注销 Token

## 四、Gateway 路由架构

Gateway 是唯一 HTTP 入口，维护 9 个 gRPC 客户端，直接代理到后端服务。

**中间件链**: CORS -> WrapResponseMiddleware -> JWTMiddleware -> AdminMiddleware

**响应包装** (`WrapResponseMiddleware`):
- 统一 `{ code, message, data }` 格式
- camelCase -> snake_case
- protobuf timestamp -> RFC3339
- 分页结构扁平化

## 五、数据层

### 数据库

**所有服务共享同一个 PostgreSQL 实例** (`makejob`)，逻辑隔离（每服务只操作自己的表）。

### 其他存储
- **Redis**: user 服务 Token 黑名单 (db:2)，其他服务用于缓存
- **Milvus**: rag 服务向量索引，collection `makejob_questions`
- **MinIO**: 对象存储(已部署，使用情况待确认)

## 八、架构特点与现状评估

### 已完成
- 15 个微服务全部拆分完成，API 定义(proto)完整
- Gateway 作为统一 HTTP 入口，REST -> gRPC 代理完成
- RabbitMQ 异步任务体系就绪，9 个队列覆盖主要异步场景
- AI 能力集中化(ai_gateway)，封装火山引擎 ARK
- 可观测性三件套(Prometheus + Grafana + Jaeger)已部署
- 服务间内部认证机制就绪

### 待改进
- **服务发现**: etcd 已部署但未启用，所有地址硬编码

- **Wire 未生效**: 引入了 Wire 但手动组装依赖
- **配置管理**: 自实现配置加载，未使用 Kratos 原生配置(远程配置中心)
