# MakeJob 项目现状总览

本文档基于当前代码状态更新于 `2026-05-15`，用于快速判断项目进度、真实边界和主要风险。

## 1. 项目定位

MakeJob 当前已经不是单一模块 Demo，而是一套围绕刷题、AI 面试、学习计划、学习陪伴、成长档案和后台运营配置构建的完整业务雏形。

当前仓库主要由三部分组成：

- `backend`：Gin + Gorm 后端服务
- `frontend-react`：React 工作区，包含前台和后台
- `docs`：当前状态文档

## 2. 当前总体进度判断

从代码状态看，项目已经进入“主流程成型，持续补齐和收口”的阶段，而不是“仅搭框架”阶段。

### 2.1 已成型主线

- 用户登录、资料与鉴权
- 题库浏览、答题、收藏、笔记、错题与推荐
- 社区发帖、评论、点赞与个人帖子管理
- AI 面试创建、答题、报告与 WebSocket 实时链路
- 学习计划生成、任务更新、反馈与调整
- 学习陪伴聊天与每日学习日志沉淀
- 成长档案聚合练习、面试、计划和周重点补强
- 后台题库、分类、行业、Prompt、AI 配置、Live2D、TTS、运行任务、题目流水线
- Worker 消费异步导入与异步题目流水线任务

### 2.2 仍依赖环境才能完整验证的能力

- 第三方 AI 模型能力
- TTS / ASR 真实服务
- Live2D 资源与运行时效果
- Piston 代码执行链路

这些能力已经在代码中落位，但完整体验依赖外部服务和数据。

## 7. 当前主要风险

### 7.1 文档和代码曾经存在偏差

旧文档里曾出现“仍是骨架 / 占位页”之类表述，但当前代码已明显超出那个阶段。本次文档重写的目的就是消除这类误判。

### 7.2 环境与配置风险

- 当前默认配置依赖本地 PostgreSQL、Redis 和可选 Piston。
- 第三方 AI、TTS、ASR 配置会直接影响功能体验。
- 接手前应优先清点敏感信息治理和环境变量策略。

### 7.3 少量前端工程瑕疵

后台构建当前仍存在少量 CSS 压缩告警，但不阻塞产物生成，属于后续可清理项。
